# Tuning Record: Scheduled Task Created

**Platform:** Elastic Stack 9.2.4. Before: ES|QL over Sysmon Event ID 1. After: ES|QL over Windows Security Event ID 4698. 3 Windows 11 lab hosts.
**Technique:** T1053.005 Scheduled Task/Job: Scheduled Task
**Date:** 2026-10-12

## Before
- Volume: 93 firings over 2026-10-11T00:00Z – 2026-10-12T20:00Z (hosts reported data in 17 of those hours)
- Hosts affected: 3
- Alerts per host: 31.0 (windows-lab 51, tuning-host3 24, tuning-host2 18)
- True positives: **1 of 2** atomic executions detected:
  - Detected: T1053.005-2 at 2026-10-12T18:59:37.690Z (`SCHTASKS /Create /SC ONCE /TN spawn ...`)
  - Missed: T1053.005-4 at 19:01:38.877Z, which created `\AtomicTask` via `Register-ScheduledTask`
    (Task Scheduler API), so `schtasks.exe` never ran
  - Not counted: T1053.005-7 at 19:03:39.795Z produced no payload process. Defender blocked its
    command line before the process started (`Trojan:Win32/Commandrob.A!ml`, confirmed in
    `evidence/defender-events.csv`), so it cannot be scored either way.
- False positive rate: 92 of 93 = **98.9%**
- Top noise sources (all parent `powershell.exe`, user SYSTEM):
  - 44 (3 hosts): `schtasks /create /tn ContosoUpdater\ContosoUpdateTaskMachineCore ... /f`
  - 44 (3 hosts): `schtasks /create /tn ContosoUpdater\ContosoUpdateTaskMachineUA ... /f`
  - 4 (1 host): `schtasks /create /tn ContosoIT\LegacyPrinterReport ...`

## Hypothesis
Written after inspecting the missed atomic's time slot, before changing the rule:
1. The miss is a **data-source problem, not a logic problem.** The rule watches one tool
   (`schtasks.exe`). No query change can see a task created through the API. In the missed slot,
   Security 4698 (`\AtomicTask`) and Sysmon 11 (file write to `C:\Windows\System32\Tasks\AtomicTask`)
   both fired, so the outcome *is* visible, just not in process events.
2. Moving to 4698 changes the noise profile entirely, so the old noise analysis does not carry over
   and the 4698 population must be profiled from scratch.

## Change
Technique: **narrow on behavior**, here meaning detect the *outcome* (a task
now exists) instead of one *tool* that creates tasks, followed by the **narrowest possible
exceptions** (technique 5), anchored on the task's action rather than its name.

Profiling 4698 over the same window found 37 events: 27 Contoso backup-verify tasks (svc_backup,
timestamped names), 6 Windows SoftLanding tasks (tips/notifications, COM handler, no executable),
2 Google Updater tasks, and the 2 atomics.

**Before** (`detections/before/T1053.005-schtasks-create.esql`):

```sql
// LOOSE "BEFORE" RULE - deliberately naive. Do not deploy.
// Name:      Scheduled Task Created via schtasks.exe
// Technique: T1053.005 Scheduled Task/Job: Scheduled Task
// Logic:     any schtasks.exe process whose command line contains /create
// Why naive: single dimension, no exclusions, written without looking at our own data.
//            Also blind by design to tasks created through the Task Scheduler API (no schtasks.exe).
FROM logs-windows.sysmon_operational-*
| WHERE event.code == "1"
    AND process.name == "schtasks.exe"
    AND TO_LOWER(process.command_line) LIKE "*/create*"
| KEEP @timestamp, host.name, user.name, process.parent.name, process.command_line
```

**After** (`detections/after/T1053.005-scheduled-task-created.esql`):

```sql
// TUNED "AFTER" RULE
// Name:      Scheduled Task Created
// Technique: T1053.005 Scheduled Task/Job: Scheduled Task
// Before:    detections/before/T1053.005-schtasks-create.esql
//
// DATA SOURCE CHANGED: Sysmon process events (schtasks.exe /create) -> Security event 4698.
//   The old rule watched one TOOL. Atomic T1053.005-4 used Register-ScheduledTask (Task Scheduler
//   API), so schtasks.exe never ran and the old rule could not see it. 4698 records the OUTCOME
//   - a task now exists - whichever tool made it. Requires audit policy "Other Object Access
//   Events" (Success); check that is enabled fleet-wide before trusting this rule.
//
// KNOWN BLIND SPOT: overwriting an EXISTING task (schtasks /create /f, Set-ScheduledTask) logs
//   4702 "updated", not 4698. An attacker who hijacks an existing task's action is invisible here.
//   4702 is very noisy (Windows updates its own tasks constantly), so it needs its own rule that
//   compares a task's action against its known-good baseline. Not built yet.
//
// EXCLUSIONS - anchored on what the task RUNS, not what it is called (names are attacker-chosen):
//   1. Contoso backup verify: everything pinned except the timestamp, which must be digits in
//      exactly that shape ("template match"). Created by svc_backup only.
//   2. Windows SoftLanding (tips/notifications): no executable at all, only one of two known
//      built-in COM handler CLSIDs. A COM-handler task with any other CLSID still alerts.
//   3. Google Updater: action must be updater.exe under Program Files (admin-only writable),
//      created by the machine account (SYSTEM).
//
// Regex note: a literal " cannot end a triple-quoted ES|QL string, so quote characters in the
// patterns below are matched with "." (any single character).
// NULL SAFETY: exclusion flags use COALESCE(..., false) - see the T1059.001 after rule.
FROM logs-system.security-*
| WHERE event.code == "4698"
| GROK winlog.event_data.TaskContent "<Command>%{DATA:task_cmd}</Command>"
| GROK winlog.event_data.TaskContent "<Arguments>%{DATA:task_args}</Arguments>"
| GROK winlog.event_data.TaskContent "<ClassId>%{DATA:task_clsid}</ClassId>"
| EVAL task_name = winlog.event_data.TaskName,
       creator   = winlog.event_data.SubjectUserName
| EVAL is_backup = COALESCE(
        creator == "svc_backup"
        AND task_name RLIKE """\\ContosoBackupVerify_[0-9]{12}"""
        AND task_cmd == "powershell.exe"
        AND task_args RLIKE """-NoProfile -WindowStyle Hidden -Command .Get-ChildItem 'C:\\ProgramData\\ContosoIT\\backup\\staging-[0-9]{8}-[0-9]{6}' \| Measure-Object \| Out-Null.""", false),
       is_softlanding = COALESCE(
        task_name LIKE """\\SoftLanding\\S-1-5-21-*"""
        AND task_cmd IS NULL
        AND task_clsid IN ("{F47D8C53-0B74-4A66-959D-367710AB1F84}", "{AF28889E-B0FD-494C-9FB0-D3B058A96B34}"), false),
       is_google = COALESCE(
        creator LIKE "*$"
        AND task_cmd RLIKE """.C:\\Program Files \(x86\)\\Google\\GoogleUpdater\\[0-9.]+\\updater\.exe.""", false)
| WHERE NOT (is_backup OR is_softlanding OR is_google)
| EVAL process.command_line = CONCAT(COALESCE(task_name, "?"), "  ->  ", COALESCE(task_cmd, CONCAT("COM ", task_clsid), "?"), " ", COALESCE(task_args, ""))
| KEEP @timestamp, host.name, creator, task_name, task_cmd, task_args, process.command_line
```

Why this technique over the alternatives:
- Any exclusion added to the old rule would have reduced noise while leaving the API-creation
  blind spot in place: a quieter rule that is still blind.
- **Exclusions anchor on what the task runs, not what it is called.** Task names are chosen by the
  creator, so an attacker can name a task `\GoogleSystem\GoogleUpdater\...`. The Google exclusion
  instead requires the action to be `updater.exe` under `C:\Program Files (x86)\Google\...`
  (admin-only writable) and the creator to be the machine account.
- **Template match for the backup task:** its arguments differ only by a timestamp, so every
  character is pinned except that slot, which must be exactly `[0-9]{8}-[0-9]{6}`.
- **SoftLanding** is allowed only with no executable *and* one of the two built-in COM handler
  CLSIDs observed. A COM-handler task with any other CLSID still alerts (COM-handler tasks are
  themselves a persistence technique).

## What this gives up
- **Task overwrites (4702) are now invisible.** `schtasks /create /f` on an existing task, or
  `Set-ScheduledTask`, logs 4702 "updated", not 4698. That is exactly why the 88 Contoso updater
  alerts disappeared: they were never "created". An attacker who replaces the action of an
  existing legitimate task is not seen by this rule. 4702 fires constantly as Windows maintains
  its own tasks, so covering it needs a separate rule comparing each task's action to a known-good
  baseline. **Not built.**
- **Audit policy dependency:** 4698 exists only if "Audit Other Object Access Events" (Success) is
  enabled. On hosts without it, this rule is silent, which is worse than the old rule there.
- **Backup template:** a malicious task created by `svc_backup` with the exact backup-verify shape
  is excluded. Its payload is fixed to a harmless `Get-ChildItem | Measure-Object`, so exploiting
  that requires changing nothing.
- Gains: tasks created by any tool (schtasks, PowerShell, WMI, COM, direct API) are now seen.

## Validation
- All 2 atomic executions still detected: **yes** (previously 1 of 2)
- Volume delta: 93 → 2 (**97.8% reduction**). Remaining: `\spawn` → `cmd.exe`, `\AtomicTask` → `calc.exe`.
- Per-exclusion check: of 37 events, backup removed 27, SoftLanding 6, Google 2, no overlaps,
  2 left = all accounted for.
- Anything that stopped firing which should not have: the Contoso updater re-registrations. Benign
  here, but they mark the 4702 blind spot described above.
- **Caveat:** tuned and validated on the same data window. No held-out window yet.
