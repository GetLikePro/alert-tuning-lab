# Tuning Record: Encoded PowerShell Command

**Platform:** Elastic Stack 9.2.4 (ES|QL over Sysmon Event ID 1), 3 Windows 11 lab hosts
**Technique:** T1059.001 Command and Scripting Interpreter: PowerShell
**Date:** 2026-10-12

## Before
- Volume: 113 firings over 2026-10-11T00:00Z – 2026-10-12T20:00Z (hosts reported data in 17 of those hours)
- Hosts affected: 3
- Alerts per host: 37.7 (windows-lab 65, tuning-host3 25, tuning-host2 23)
- True positives: **0 of 2** encoded payloads detected. Atomic payloads ran at
  2026-10-12T19:05:43.298Z (T1059.001-15, `powershell.exe -NoProfile -E ...`) and
  19:07:43.955Z (T1059.001-17, `powershell.exe -e ...`). Both missed.
  One firing (19:05:40.567Z) did coincide with an atomic, but it matched the *test harness* line
  `Out-ATHPowerShellCommandLineParameter -EncodedCommandParamVariation E`, only because the text
  "-enc" appears inside that parameter name. That is a coincidence, not a detection.
- False positive rate: 112 of 113 firings benign = **99.1%** (100% if the harness hit is not credited)
- Top noise sources:
  - 75 (3 hosts): Contoso inventory agent, SYSTEM, `svchost.exe -s Schedule` → `powershell.exe -EncodedCommand JgAgAEMA...`
    (decodes to `& C:\ProgramData\ContosoIT\jobs\inventory.ps1`; byte-identical every run)
  - 33 (3 hosts): Contoso RMM tool, `it.admin`, parent `powershell.exe -File ...\adminscript.ps1`,
    a different encoded payload every run (embedded ticket number + timestamp + random checks)
  - 4 (1 host): Contoso printer report, SYSTEM, parent `...\reporttool.ps1`

## Hypothesis
Written after decoding every noisy payload, before changing the rule:
1. The rule is **blind**, not just noisy. PowerShell accepts any prefix of `-EncodedCommand`
   (`-e`, `-en`, `-enc`, ...), plus `-ec` on pwsh, `/` instead of `-`, and Unicode dashes. A
   literal match on `-enc` misses the shortest and most common attacker form, `-e`.
2. All benign volume comes from three management tools. Two have a fixed payload and can be
   pinned exactly. The third (RMM) varies every run, so it can only be identified by context.

## Change
Technique: **widen the match first, then the narrowest possible exceptions**,
each anchored on process identity rather than a path (technique 2).

**Before** (`detections/before/T1059.001-powershell-encoded.esql`):

```sql
// LOOSE "BEFORE" RULE - deliberately naive. Do not deploy.
// Name:      Encoded PowerShell Command
// Technique: T1059.001 Command and Scripting Interpreter: PowerShell
// Logic:     any powershell.exe launched with -enc / -EncodedCommand
// Why naive: single dimension, no exclusions. Legitimate management tools encode constantly.
FROM logs-windows.sysmon_operational-*
| WHERE event.code == "1"
    AND process.name == "powershell.exe"
    AND TO_LOWER(process.command_line) LIKE "*-enc*"
| KEEP @timestamp, host.name, user.name, process.parent.name, process.command_line
```

**After** (`detections/after/T1059.001-powershell-encoded.esql`):

```sql
// TUNED "AFTER" RULE
// Name:      Encoded PowerShell Command
// Technique: T1059.001 Command and Scripting Interpreter: PowerShell
// Before:    detections/before/T1059.001-powershell-encoded.esql
//
// WIDENED (fixes misses found by atomics T1059.001-15 and -17, which used -E and -e):
//   - PowerShell accepts ANY prefix of -EncodedCommand (-e, -en, -enc ... -encodedcommand), and
//     pwsh also accepts -ec. The old LIKE "*-enc*" missed -e and -E entirely.
//   - Switch may start with / or a Unicode dash (en dash, em dash, horizontal bar), all of which
//     PowerShell treats as "-".
//   - Requires a base64-looking argument after the switch, so text like
//     "-EncodedCommandParamVariation" does not match.
//   - Matches on the PE OriginalFileName too, so a renamed powershell.exe is still caught.
//
// NARROWED - three known-benign sources, each excluded as tightly as its data allows:
//   1. Contoso inventory agent: byte-identical command line every run -> exact command line
//      + SYSTEM. Residual risk: whoever can edit inventory.ps1 inherits this exclusion.
//      Verify the ACL on C:\ProgramData\ContosoIT\jobs (ProgramData is user-writable by default).
//   2. Contoso printer report: exact command line + exact parent script + SYSTEM.
//   3. Contoso RMM tool: payload is unique every run, so the command line cannot be pinned.
//      Excluded by context: user it.admin + exact parent script. WEAKEST exclusion - a stolen
//      it.admin account running through adminscript.ps1 is invisible to this rule. Compensate
//      with 4104 script-block content rules, which this exclusion does not touch.
//
// NULL SAFETY: each exclusion is computed as a flag with COALESCE(..., false). A bare
// WHERE NOT (process.parent.command_line == "...") evaluates to null when the parent is
// missing, and ES|QL drops null rows - which would silently hide attacks with no parent info.
FROM logs-windows.sysmon_operational-*
| WHERE event.code == "1"
    AND (process.name IN ("powershell.exe", "pwsh.exe")
         OR process.pe.original_file_name IN ("PowerShell.EXE", "pwsh.dll"))
| EVAL cl = TO_LOWER(process.command_line)
| WHERE cl RLIKE """.*[ "][-/–—―](ec|e|en|enc|enco|encod|encode|encoded|encodedc|encodedco|encodedcom|encodedcomm|encodedcomma|encodedcomman|encodedcommand) +["']?[a-z0-9+/=]{16,}.*"""
| EVAL is_inventory = COALESCE(
        user.name == "SYSTEM"
        AND process.command_line == """"powershell.exe" -NoProfile -NonInteractive -WindowStyle Hidden -ExecutionPolicy Bypass -EncodedCommand JgAgAEMAOgBcAFAAcgBvAGcAcgBhAG0ARABhAHQAYQBcAEMAbwBuAHQAbwBzAG8ASQBUAFwAagBvAGIAcwBcAGkAbgB2AGUAbgB0AG8AcgB5AC4AcABzADEA""", false),
       is_printer = COALESCE(
        user.name == "SYSTEM"
        AND process.parent.command_line == """"powershell.exe" -NoProfile -NonInteractive -WindowStyle Hidden -ExecutionPolicy Bypass -File C:\ProgramData\ContosoIT\jobs\reporttool.ps1"""
        AND process.command_line LIKE """*-EncodedCommand RwBlAHQALQBDAGkAbQBJAG4AcwB0AGEAbgBjAGUAIABXAGkAbgAzADIAXwBQAHIAaQBuAHQAZQByACAAfAAgAEUAeABwAG8AcgB0AC0AQwBzAHYAIABDADoAXABQAHIAbwBnAHIAYQBtAEQAYQB0AGEAXABDAG8AbgB0AG8AcwBvAEkAVABcAGkAbgB2AGUAbgB0AG8AcgB5AFwAcAByAGkAbgB0AGUAcgBzAC4AYwBzAHYAIAAtAE4AbwBUAHkAcABlAEkAbgBmAG8AcgBtAGEAdABpAG8AbgA=*""", false),
       is_rmm = COALESCE(
        user.name == "it.admin"
        AND process.parent.command_line == """"powershell.exe" -NoProfile -NonInteractive -WindowStyle Hidden -ExecutionPolicy Bypass -File C:\ProgramData\ContosoIT\jobs\adminscript.ps1""", false)
| WHERE NOT (is_inventory OR is_printer OR is_rmm)
| KEEP @timestamp, host.name, user.name, process.parent.name, process.command_line
```

Why this technique over the alternatives:
- **Prevalence baselining was rejected.** The inventory payload is on 3 of 3 hosts, so prevalence
  would suppress it, but with a 3-host fleet any threshold that does that also suppresses an
  attacker who runs on two hosts. Prevalence also cannot handle the RMM payload, which is unique
  every time and would never reach any threshold.
- **Exclusion strength was matched to the data.** Inventory: exact command line (strongest).
  Printer: exact command line + exact parent. RMM: user + exact parent script (weakest, because
  the payload varies).
- **Null safety:** each exclusion is a flag wrapped in `COALESCE(..., false)`. A bare
  `WHERE NOT (parent == "x")` evaluates to null when the parent is missing (5 inventory events had
  no parent), and ES|QL drops null rows, which would silently hide attacks with no parent info.

## What this gives up
- **RMM channel:** anything run as `it.admin` through `adminscript.ps1` with an encoded command is
  invisible to this rule. A stolen `it.admin` credential or a modified `adminscript.ps1` hides
  here. Compensating control: PowerShell 4104 script-block logging records the decoded content
  regardless of launcher, and content-based rules on 4104 are untouched by this exclusion.
- **Inventory script:** whoever can modify `C:\ProgramData\ContosoIT\jobs\inventory.ps1` gets
  code execution under an excluded command line. `C:\ProgramData` is user-writable by default, so
  the folder ACL must be verified (not done in the lab).
- **Short payloads:** the regex requires 16+ base64 characters after the switch. An encoded
  command under ~12 decoded characters would be missed. Accepted as low risk.
- Gains, too: `-e`, `-E`, `/e`, `-ec`, Unicode-dash variants and renamed `powershell.exe` (via
  `OriginalFileName`) are now caught.

## Validation
- All 2 atomic executions still detected: **yes** (and neither was detected before)
- Volume delta: 113 → 2 (**98.2% reduction**). Both remaining firings are the atomic payloads.
- Anything that stopped firing which should not have: the harness-line coincidence no longer
  fires. Correct, since it was never a real detection.
- Logic tested against 11 synthetic command lines (all abbreviations, `/`, en/em dash, pwsh `-ec`,
  `-ep bypass -enc`, plus 2 benign non-encoded lines): 11/11 correct.
- **Caveat:** tuned and validated on the same data window. No held-out window yet.
